## Conversion pipeline implementation update

The earlier implementation proposal has been replaced. The implementation in `scripts/convert.ts` uses a deliberate
two-step flow so a model cannot publish unreviewed content:

1. `npm run convert -- <arxiv-id-or-url>` or `npm run convert -- <company-blog-url> --archive-url <url> --archive-retrieved-on YYYY-MM-DD`
   fetches and converts the source, then writes a **local draft only**. It does not modify Supabase or run `seed:editorial`.
2. Review the story JSON, AI-draft fact-check ledger, SVG files, and tag associations. Tag associations start `suggested`; approve
   only accepted links to existing vocabulary. New tags are proposals only and are not seeded. For arXiv papers, the default trust
   is `preprint`; pass `--trust peer_reviewed` only after independently confirming the venue. Blog trust is fixed to
   `company_reported`.
3. `npm run convert -- --publish-preview <slug>` verifies duplicate slugs, required metadata, tag approval, and visibility through
   `v_preview_story`, then calls the existing `publish:supabase` command. Review with `VITE_SHOW_PREVIEW=1 npm run dev`; approve live
   separately with `npm run approve -- <slug>`.

The converter accepts arXiv HTML sources and public HTTP(S) blog pages. PDF-only arXiv entries fail with a useful message. Source
requests enforce public-address DNS pinning, redirect revalidation, byte limits, and a 45-second overall deadline. Anthropic results
are checkpointed before JSON parsing, so a malformed paid response can be inspected under ignored `data/intake/`. Generated Python
is never run: illustrations must be SVG markup, parsed and checked by the fixed validator in `scripts/convert/artifacts.ts`.

Blogs require an archive URL and real retrieval date; the date is carried into `BlogSource.retrievedOn` for the publisher's
`source_snapshot` row. The converter checks the URL's syntax but does not verify that the archive service actually serves the
requested capture; the owner must verify that before approving the draft.

No Anthropic API conversion has been run as part of implementation review. Running it spends the owner's API budget. Local
verification covers typecheck, lint, build, and command help only; the first real conversion remains an explicit acceptance step.
