## The next batch: automated conversion pipeline

### Goal

Single command:

```
npm run convert -- <arxiv-id-or-url>
```

Turns a paper or company blog post into a `preview`-status story on Supabase — fetched, converted, fact-checked, tagged, illustrated with real Python-generated SVGs, wired into `data/seed/library.json`, and published. Owner reviews in dev, then `npm run approve <slug>` to flip live.

### Pipeline

Orchestrator: new `scripts/convert.ts`. Calls Claude via `@anthropic-ai/sdk` from Node. Reads `ANTHROPIC_API_KEY` from `.env`.

Stages, each a Claude SDK call with the relevant `skills/<name>/SKILL.md` as system prompt:

1. **Fetch.** Resolves `arxiv:NNNN.NNNNN` or `NNNN.NNNNN` to arXiv PDF URL, or accepts an HTTP URL. Downloads to `data/intake/<slug>.pdf` / `.html`. Infers slug from URL/title (lowercase-kebab, verified unique against `v_live_story` + `v_preview_story`).
2. **Classify.** Paper vs blog, slug, desk, trust. For arXiv: default `preprint`. Blog: `company_reported`. Peer-reviewed venue (CVPR/SOSP/NeurIPS/WWW etc) confirmed from title page: `peer_reviewed`. Default conservatively to `preprint` on uncertainty — matches the gotcha below.
3. **Convert.** `skills/convert-paper/SKILL.md` + `skills/explain-source/SKILL.md` as system prompt. Produces `data/seed/papers/<slug>.json` matching the shape of `data/seed/papers/attention-is-all-you-need.json`. Must set `schemaVersion: 2`, correct `kind`, `desk`, `cover` or `hook`, every fact with `claim: model_design | measured_result`, every tag with `source` and `status`.
4. **Fact-check.** `skills/fact-check/SKILL.md`. Produces `docs/fact-checks/<slug>.md` matching the format of `docs/fact-checks/attention-is-all-you-need.md`. One row per claim: claim, quoted evidence, section anchor, pass/weak/fail.
5. **Tag.** `skills/tag-story/SKILL.md`. Reads existing vocabulary from `data/seed/tags.json`. Infers tags for the story. New tags are proposed inline in the story file (`proposed` block) AND appended to `tags.json`. **Auto-approve new tags during V1** (set `status: approved` on new tags in the story file; owner will review in the admin page later). This avoids the publish-rejection we hit before.
6. **Illustrate.** `skills/draw-illustrations/SKILL.md`. Reads `tools/draw_attention.py` and `tools/media_kit.py` as the pattern reference. Writes `tools/draw_<slug>.py` that produces every SVG the story JSON references (lead, comic, story, facts). Executes it via `python3 tools/draw_<slug>.py`. Verifies each file exists, is valid XML, has the right `viewBox`, and the `<title>` matches the `media.alt` in the story JSON.
7. **Wire library.** Mutates `data/seed/library.json`:
   - Append to `stories[]` with `{id, real: true, sample: false, kind, trust, role, fields, headline, accent, dek, desk, title, authors, year, minutes}`.
   - Append to `nodes[]` with `{id, title, short, authors, year, field, type, x, y, story, blurb}`. Coordinates chosen inside the field's cluster (see `fields[].cluster` in library.json).
   - **Do NOT auto-add relations** unless the source paper itself cites a node already in the library. If it does, add `{from, to, kind, note, cited: true}`. Otherwise skip — the owner adds relations later.
8. **Seed + publish.** Spawns `scripts/seed-editorial-from-library.ts` (`npm run seed:editorial`) then `scripts/publish-to-supabase.ts <slug>` (which defaults to `--status preview`).
9. **Verify.** Queries `v_preview_story` to confirm one row with `story_slug = <slug>`. Reports the dev URL (`http://localhost:5173/papers/<slug>`).
10. **Report.** Prints: files written, tag additions, library changes, dev URL, slug, status (`preview`), and "run `npm run approve -- <slug>` when ready".

- Opus only if a paper runs long and Sonnet hits context limits.

### Error handling

- Each stage writes a checkpoint to `data/intake/<slug>.state.json` (`{stage: "convert", completed: ["fetch", "classify"], ...}`). A re-run of `npm run convert -- <slug>` resumes from the last completed stage.
- Stage failures print the stage name + the error, don't auto-retry, leave partial writes in the working tree for human review.
- No automatic rollback of DB publishes. The preview-status gate means a bad publish stays in preview and doesn't affect the hosted site.

### Gotchas (these bit us in the manual conversion)

1. **Tag status rejection.** Publisher aborts if any tag has `status: "suggested"` in the story JSON. Auto-approve the tags you propose (set `status: "approved"` after writing them to `tags.json`).
2. **Trust is required and enum-constrained.** `trust` must be exactly one of `peer_reviewed | preprint | company_reported`. `undefined` is rejected. On uncertainty default to `preprint`.
3. **Library merges race.** If you run concurrent agents writing to `library.json` they clobber each other. Serialize the wire step, or use per-paper patch docs merged by the orchestrator.
4. **`.env` not auto-loaded.** Node needs `--env-file=.env` on every script that reads env vars. Follow the existing pattern.
5. **PATH / nvm.** Owner's shell loses nvm paths. Don't rely on `node` being on the user's PATH; the npm scripts work via npm's own resolution.
6. **Field slugs.** Library fields are `ai`, `bio`, `space`, `physics`, `sw`. No `cs`. Map CS-ish papers to `sw`.
7. **Cover vs hook.** `attention-is-all-you-need.json` uses `hook` only, no top-level `cover`. Match that; a `cover` block is optional per the type.
8. **convert-paper skill is partly stale.** It mentions `public/data/*` and `npm run data`. The correct paths are `data/seed/*` and there is no `npm run data` any more (search-index.json was removed with the Supabase-only runtime).
9. **Prerender needs Supabase at build time.** `scripts/prerender-routes.ts` uses the Node Supabase client + publishable key with `--env-file=.env`. Verify your new slug appears in `prerenderRoutes()` after publish.
10. **The 3 recent papers have placeholder `preprint` trust.** CVPR/WWW7/SOSP are peer-reviewed; the agents couldn't verify from paper text and the owner approved dropping the label. If the pipeline can reliably confirm a venue (via DOI lookup, bibsonomy, etc.), it can set `peer_reviewed` with confidence.
